# Tool spec — S3 / object storage browser

**Crate:** `tool-s3` (client in `hs-core::objstore`) · **Priority:** P0 · **Status:** M2 — v1 implemented (see "Implementation status" at the end)

## 1. Purpose

Browse, transfer and inspect objects in S3 and every S3-compatible store
(MinIO, Cloudflare R2, Backblaze B2, DigitalOcean Spaces, Wasabi, Ceph RGW,
LocalStack) with the same dual-pane feel as SFTP, the same transfer queue, and
the environment guards. Azure Blob and Google Cloud Storage come later behind
the same trait.

## 2. User stories

- Import `~/.aws/credentials`; profiles appear; open `shop-assets-staging`,
  navigate `images/2026/10/`, drag a folder from the local pane; multipart
  upload with progress; a presigned link for one image is one click away.
- Open a 2 KB `config.json` object in the editor, change a value, save — a new
  version is written and the previous one is listed under Versions.
- Delete the `tmp/` prefix on production: the dialog names the bucket and
  environment and demands the bucket name typed; versioning status is shown
  so the user knows whether this is recoverable.
- Compare a local `dist/` with `s3://site/` and upload only what changed
  (dry run first).

Single pane by default with a breadcrumb; toggle a local pane (dual-pane like
SFTP) for drag transfers. Each tab is one profile (bucket navigation inside).

## 4. Client (`hs-core::objstore`)

Our own SigV4 client (`hmac` + `sha2`, verified against the AWS signature test
vectors) on async `reqwest`. Eden Explorer's `S3Fs` is a useful read for the
list-parsing and endpoint quirks of S3-compatible servers, but nothing is
copied from it. Operations:

- `ListObjectsV2` with delimiter and continuation tokens (page size 1,000);
  `ListBuckets`; `HeadObject`; `GetObject` with ranges; `PutObject`;
  multipart `CreateMultipartUpload`/`UploadPart`/`Complete`/`Abort` (part size
  adaptive 8–64 MB, concurrency 4); `CopyObject` (and multipart copy for
  > 5 GB); `DeleteObjects` batch (1,000); `ListObjectVersions`;
  `GetObjectTagging`/`Put`; `GetBucketVersioning`, `GetBucketLocation`,
  `GetBucketPolicy`, `GetBucketCors`, `GetBucketLifecycleConfiguration`
  (read-only viewers); presign GET/PUT with expiry.
- Path-style vs virtual-hosted addressing, custom endpoint, region
  auto-detect from `x-amz-bucket-region`, checksum (SHA-256 / CRC32C) on
  upload, retries with backoff on 5xx/throttling, request signing of
  streamed bodies via `UNSIGNED-PAYLOAD` over TLS.
- Credentials: static keys (SecretRefs), session token, `~/.aws/credentials`
  + `config` profiles including `source_profile`/`role_arn` via STS
  `AssumeRole` (P1), SSO (P2), instance/container metadata (P2).
- `ObjectStore` trait so Azure Blob (shared key / SAS) and GCS (HMAC
  interop or service account) can be added as P2.

## 5. Browsing

- Lazy prefix navigation with breadcrumb and editable path (`s3://bucket/
  prefix/`), back/forward, bookmarks per profile, "load more" and
  "load all" (with count warning), prefix filter box (server-side `Prefix`),
  client-side name filter on the loaded page, sort by name/size/date/class,
  hidden "folder marker" objects shown optionally.
- `DataTable` columns: name, size, modified, storage class, ETag, owner (if
  returned), versions (lazy), tags (lazy); column chooser.
- Details pane: metadata (system and user `x-amz-meta-*`, editable with a
  copy-in-place `CopyObject`), tags editor, storage class change, versions
  list with download/restore/delete, presign generator (method, expiry,
  response headers), public URL when the bucket allows, copy `s3://` URI /
  ARN / HTTPS URL.
- Bucket panel: region, versioning, encryption, policy JSON (read-only
  viewer, `hs-editor`), CORS, lifecycle rules table, approximate size and
  object count (from a background scan, cached) (P1).

## 6. Transfers

Shared `Transfers` service with SFTP: queue with per-profile concurrency,
multipart uploads, ranged parallel downloads, resume (multipart upload ids are
persisted so an interrupted upload resumes; downloads resume by range),
conflict rules, speed/ETA, retry/pause/cancel, verify by checksum, history.
Drag and drop from the OS and between panes/tabs (SFTP ↔ S3 streams through
the client without a local temp copy when possible). Folder upload keeps
relative keys; "upload as" lets the user set storage class, content type
override, cache headers, metadata and tags for the batch.

## 7. Operations

Create "folder" (zero-byte marker, optional), rename (copy + delete, warns on
large objects), move/copy within and across buckets and profiles, delete
(batch, versioned-aware: "delete marker" vs "permanently delete version"),
download to folder, open in editor (`s3://` VFS; writes do a full `PutObject`,
keeping content type and metadata), open with local app (temp + watch + re-put),
"empty prefix" (guarded), restore from Glacier (P1), change storage class in
bulk (P1).

## 8. Sync (P1)

Compare local folder ↔ prefix (or prefix ↔ prefix across profiles) by size +
mtime or ETag/MD5 (single-part) or checksum; show added/changed/removed; mirror
one way with delete option; dry run first; exclude patterns; save as a named
sync task re-runnable from the sidebar or the palette. Same engine as SFTP
sync.

## 9. Guards

Protected environments: deletes beyond 10 objects or any prefix require the
bucket name typed; overwrite confirmation shows the existing object's version
status; bucket policy/CORS/lifecycle are read-only viewers in v1 anyway.
Presigned URL generation shows a warning when the expiry exceeds 7 days
(SigV4 maximum) and when the bucket is public.

## 10. Connections

`kind = "s3"` profile: provider hint (sets endpoint/path-style defaults),
endpoint, region, access key id, secret (SecretRef), session token (SecretRef),
path-style, default bucket, SSE defaults, tags/colour/environment. Import from
AWS files (profiles listed, choose which), from `rclone.conf` S3 remotes (P1),
from MinIO Client aliases (P1).

## 12. Tests

SigV4 known-answer tests (AWS test suite vectors), list parsing with
continuation and delimiter edge cases (keys with `//`, unicode, `+`), multipart
resume after kill, path-style/virtual-host URL building, integration against
MinIO and LocalStack containers.

## 13. Implementation status (M2, 2026-10-11)

What exists, and where it differs from the sections above:

- **Client** (`hs-core::objstore`): `sigv4` (header signing and presigned
  queries, checked against AWS's published examples: the sig-v4 test
  suite's `get-vanilla`, and the S3 GET-with-range, PUT and presigned-URL
  examples), `xml` (a small element reader for S3 responses: entities,
  CDATA, namespaces dropped), `s3` (`ListBuckets`, `ListObjectsV2` with
  delimiter and continuation, `HeadObject`, `GetObject` to memory or
  streamed to a file, `PutObject`, multipart create/part/complete/abort
  with 8 MiB+ parts four in flight above 16 MiB, `DeleteObject`,
  `DeleteObjects` in batches of 1,000 with Content-MD5, `CreateBucket`,
  `DeleteBucket`, `GetBucketVersioning`, presign GET/PUT). Path-style or
  virtual-hosted (dotted buckets fall back to path style), region learnt
  from `x-amz-bucket-region` and retried once, retries with backoff on
  5xx/429/connect errors. Payloads are hashed (not `UNSIGNED-PAYLOAD`) since
  parts are read into memory anyway. No checksum headers, ranged/parallel
  downloads, copy, tagging, versions list or bucket-policy viewers yet.
- **Profiles** (`hs-core::objstore::profile`): `S3Fields` with provider
  presets (AWS, MinIO, R2, B2, Spaces, Wasabi, other), a Settings →
  Connections form for kind S3 whose secret key and session token go into
  the vault on save, and import from `~/.aws/credentials` + `~/.aws/config`
  (or `AWS_SHARED_CREDENTIALS_FILE`/`AWS_CONFIG_FILE`): profiles with static
  keys are listed, the chosen ones become connections, keys into the vault,
  `endpoint_url` kept. STS/SSO profiles are skipped.
- **Tool** (`tool-s3`): sidebar with profiles and the selected profile's
  buckets; bucket list; browser with breadcrumb, name/size/modified/class/
  ETag columns, client-side filter and sort, 1,000 keys per page with
  **Load More**; toolbar Up, Refresh, Upload (files, as Jobs with byte
  progress and cancel), Download (streamed to `.part`, then renamed), New
  Folder (zero-byte marker), Edit (download to `HyperStackData/tmp/s3/…`,
  open in the editor, saving puts it back with its content type; up to
  32 MB), Presigned URL (GET/PUT, 15 min to 7 days, copy), Delete.
  Double-click opens folders and edits files. The tab follows the
  profile's environment; a tab restored at start-up connects once the
  vault is unlocked.
- **Guards**: deleting a prefix, or anything while the profile's (or the
  active) environment is protected, requires typing the bucket name; the
  dialog states whether versioning is on, suspended or off.
- **Not yet**: the `s3://` VFS (the editor round trip uses a temp file like
  SFTP's), the shared `Transfers` queue with resume, local pane and drag
  and drop, folder upload/download, rename/copy/move, metadata/tags/
  versions panels, sync, bucket panel, the §11 shortcuts beyond the palette
  commands, Azure/GCS.
- **Tests**: unit tests for SigV4, XML, listing/error parsing, URLs,
  presign, part sizes, profiles and AWS file parsing;
  `crates/hs-core/tests/s3_live.rs` runs the whole client against a live
  S3-compatible server when `HS_S3_ENDPOINT` is set (moto server or MinIO:
  buckets, odd keys, delimiter, paging, a 20 MiB multipart upload,
  download, presigned GET, batch delete, bucket removal).
